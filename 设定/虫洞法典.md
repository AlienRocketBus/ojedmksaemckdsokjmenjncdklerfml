# 虫洞法典（现行最优之法·活档）

> **版本 v1.8（1013）**。作者令（1009）：「每次总结方法——具体流程、具体制作过程、所踩之坑；一次又一次之经验，让虫洞方法不断升级进化，每一次都把坑修掉，让它成为最好的方法。」
> 本档只记两样：**现行最优之法**、**它从哪里来**。细节各指其档。
> 每一件任务复盘之後：
> - 新坑入 `设定/方法坑账.json`，修到「已守」。
> - 法有变，本档升一版，记入「五、版本史」。
> - `设定/方法账.md` 记一行。
>
> ⛔一成不变。⛔坑只记不修。

## 一、宗旨与律（一页）

- **唯一不改之事**：这本书是中国第一的小说，剧情是 100 分的剧情。此外一切皆可改，本法亦然。
  - **⛔固定之规限创作（作者 1015）**：「对于所有的事情没有一个固定的规则——有规则就会限制创新」。凡人物之护栏、写法之律、检察官之文体之闸，**皆是默认**：能说出「破之则书更好看在哪一页、哪一拍」者即可破（记其由），说不出即守。器之审（每回大审）专看：哪一道闸只是把写法钉成一个模子而於书无益——即升级或淘汰。
- **两大铁律**：剧情全中国最好看；剧情与逻辑之闭环绝对完美。
- **★省律（1021 作者问「怎么这么费 token，有点耗不动」·`设定/裁_1021_省律.md`）**：省要省在「这件该不该做」，不只「这件怎么做省」——①七三之律：每段之钱 ≥七成在新章与造剧情，非写章之件只许「挡下一章」或「读者读得到」二种，余入瑕疵总账⛔开工作流；②驳只驳文（正文、圣经、canon、剧情），器之改造席自测与变异即交；③主环瘦：一章一令、封一章即交接换会话，主环每章 ≤$5；④执笔共料、执笔之数二试於 401。
- **虫洞之律**：一法须**更好又更省**（作者 1015 正：⛔只「好而省」——须比他法之果更好、费更省），两样都满足才用；省下之力全投「造」。
- **★虹吸之律（1015 作者令「所有的方法都必须符合虫洞效应和虹吸效应；每一个 token 物尽其用，⛔用了八成就浪费掉」）**：池水不舀（一群人拿勺——蛮力）、不泵（买或租抽水机、耗电——昂贵）；**一根管子、借重力**，引一回，水自己流尽——**人可以去睡觉，醒来池已空，几乎无费，而其果比勺与泵更完美**（作者 1015 正）。其要四：**借势**（找本书里本来就在流的「重力」——每章之写、读、封、推，git 之史、诸席本已做之读）｜**一引**（只付一回引水之费：一器、一步）｜**无人守**（⛔主环守着看、逐步手推——主环之守即是泵）｜**果更好**（⛔省而降质）。立法前逐问：
  - **已付否**：此事要之料，是否已在别处付过（章记之「在场之人」、病册、通读、诸席之交、费账）？已付即并、⛔重付。〔W34：人物之审欲再通读全书（约 $55），查得章记逐章已记、W04 已通读审人——改为零 token 并链，读之费 $0〕
  - **一引永流**：凡会重复之需，做成流水线之一环（封版 --後、记席、全测）——引一回，此後每章自流，边际 token 为零。〔剧情链、人物链、关系链随封版重生〕
  - **顺势**：让本来就在做的事顺带产出（记席之读顺带出人物之条），⛔另起一席专为它。
  - **先量後择**：量总量（读什么最小：W34 白文 1,616,539 字 < 章记 12.6MB）、覆盖（从头到尾否）、重读之倍——择三者俱优之法。
  - **满效**：每一 token 落在要它之环——⛔席读大料而用其一角（料要薄、要准）；⛔整批开跑而一处错全死（一席小样先跑通，坑㉛）；⛔轮询与空等（候通知）。
  - **无人守否**：此法跑起来要不要主环守着、逐步手推？要即是泵——把守之活做成流之一环（封版、推、候通知），⛔主环轮询、逐步手办。〔1015 实量：主环 01:00—03:40 $30.45／281 来回，多在守与手推〕
- **★过程中进化之律（1015 作者令「在做的过程中就要不断地找瑕疵、找升级之机；在动态中进化、在过程中进化，及时发现问题；方向永远是虫洞、虹吸、完美」；D6 之痛为永远之反面教材——三十多小时、三千多万 token、九轮，一事无成，病在中途无人问「法本身错没错」）**：
  - **做者报摩擦（虹吸）**：凡席之交添一格「此法之缺」——本席做时，料缺什么、器哪里慢或错、哪一步白做；⛔另起一席找缺。诸席所报汇入瑕疵总账（W37），每回大审排序而治。
  - **里程之核**：每一环毕，主环照费审对其预估——逾 1.5 倍即停而问「法错没错」，换法或续，⛔照跑下一环（W34 审人逾 1.75 倍事後方见之教）。
  - **当场治**：过程中所逮之缺，能当场治者当场治、其治入器之自测；不能者入瑕疵总账带限。
- **★完美之律（1015 作者令「我是完美主义者——所有的一切都必须达到绝对的完美；不仅符合虫洞、虹吸，还要完美」）**：
  - **成＝独立之眼挑不出毛病**：凡交出之物（章、器、法、册），须经未参与其造之眼（驳席、盲读、负测、对照之试）找不出致命与可治之缺，方称成；⛔自己说好就算。
  - **已知之缺⛔沉默**：凡知之缺，或当下治、或入账带限（何章、何件前治）；复盘之「完美之问」逐条列之。〔W34：人物链漏十四章（章记首行带括注之式）——当下治、其式入自测〕
  - **验而⛔信**：每一断语有其证（跑、测、核）；未验者标「未验」并写其验之计。〔器之账之记：⛔待下回推送「看它灵不灵」，先以临时之档单测〕
  - **三律之序**：果求完美，法求虫洞、虹吸——⛔以省降质；⛔以完美为名而蛮力。完美之果由最省之法得之。
- **★器之进化之律（1015 作者令「工具不是设计一次就不变——要像手机 APP 一样不停升级；要发现工具之 bug 与瑕疵；不完美之器淘汰或升级；升级亦照虫洞虹吸」）**：
  - **健康之数自流（虹吸）**：每推本就跑全测——全测顺手记每检之果、之秒、之红（`_器之账.json`，存底枝存之），⛔另起一跑。
  - **定期之审（顺势）**：每回大审（十章一回）跑 `工具/囤灰闸.py --普查`——列候修（假红多、慢、钉在长大之快照）、候退（唯自测、无他调、久无红、其物已死）、新器；一席审之、一席驳之，取者照上线之律落。
  - **四问判一器**：服务目的否（护一活险、有所逮）｜虫洞（效好、秒少、席读其出之 token 少）｜虹吸（取已付之料、在流里、⛔重付）｜缺（假红、漏、脆、慢、重、死）——不合即升级或淘汰，⛔留垃圾之器。
  - **器亦有坑账**：器之假红、漏逮一经查实即入坑账，其治入其器之自测（⛔只修一回了事）。
- **名著是写出来的**：100 分从「造」来，⛔从「改」来。
  - 致命必治；大进（读者看得出之好）可治；小瑕末了一批。
  - 微改与可能改坏者⛔。
  - 停止线：独立之眼找不出致命与大进。
- **费之律**：费 ≈ Σ（来回之数 × 每回所背之上下文）。砍来回、瘦上下文，⛔砍造。
- **资源分配官之配额**：造 ≥75%｜验 ≤20%｜机器之活 → 0（归脚本）｜找料 → 0（归零 token 之料）。
- **零 token 等效之检**：机器做与模型做结果一样者，⛔花 token。
- **★先设计之律（1009 作者令）**：每做一件事之前，先想最好的办法、先设计方法；⛔硬着头皮上。开工前必答：此件哪些机器能办（归脚本）、哪些非模型不可、要多久、花多少（照费账之实）——答清了再开。
- **★效之律（1009 作者令「花很多 token 办的事，机器不花钱也能办，⛔花冤枉钱；每任务都要记效率与费，token 有没有浪费、有没有服务於最该服务之目标」）**：
  - 每件复盘之「## 效」以 $ 记：总费、服务目标之费、浪费、机器能办而花token（须 $0；非零即入坑账）。
  - 等待／轮询之费由机器自认（`费审.主环之等`）。
  - `复盘.py --效账` 汇诸件、按类比上回：总费↓、服务目标之占↑、浪费↓、机器能办＝$0——四样俱合方算进化。
- **★确证之律（1009 作者令）**：方法之每一环都要绝对精准、绝对细心——一环出错，整个方法就坏。故每一环先**确证**它能做成，再实施；⛔猜。
  - 确证须引实据：费账之键、Run、试（小样实测之命令及其果）、自测 n/n。
  - 时与费照费账同类之实，⛔凭感觉。
  - 每环写明「败则」：此环败了怎么办。
  - 尚未确证者先试；未确证有一条，即⛔开。
  - 守：`设定/方案/W.md`＋`工具/方案.py --验`，工作流账 `--开` 先验之。
- **★量法之律（1009 作者令「非常精准地算出 token 之货币量；错的方式全淘汰」）**：
  - 费一律以**美元**计。`工具/费审.py` 逐回照 `设定/价目.json`（官方价目页，注源与抓取之日）精算：按该回之模型取价；缓存写分 5m／1h 两档；缓存读按模型之倍数（Opus 5.5 为 0.05×）；产出含思考；地域、快速、网搜俱认。
  - 未能精算之回即报，⛔当零。
  - 界面所示之 token 数（通知之 subagent_tokens）只量各席末回之上下文，**只作核，⛔当实耗**。
  - 每 Run 一完即记（`费审.py --记`；复盘起草自动记）入 `设定/费账.json`。
  - 价有变即重抓官方价目页，改 `价目.json` 并记之。
  - 已淘汰：逐行相加（计重）、以界面之数当实耗、凭记忆之「等效」折算（坑⑯⑲）。
  - **精准之证**：`python3 工具/费审对拍.py`——结构全异之 SQLite 算器逐单位对拍（来回、四项 token 个位、美元到十亿分之一），并核记录之义（同一调用之诸行：前行是流式中途之数，末行恒为终值）；入全测，二十七秒、零 token。费账覆全会话（`费审.py --记全`）。
  - **不可量者明列**：工具内部之小模型调用（WebFetch 之摘要等）不入转录；本地亦无 Claude Code 自记之成本数可对。
- **★进化之律（1009 作者令·极要）**：方法进化之时，先看曾经踩过的坑——**踩过的坑⛔在新法里再现**。
  - 新法之设计档须有「## 坑之检」，逐坑写其排除之法；漏一坑，新法⛔立。（1027：只验档首书「状：待立」之 `设定/方法升级_*.md`——已立者档首书「状：已立」、其坑之检係史；W75 起之 `设定/方案/W.md` 须有「## 坑之检」，改尺者列「消费者：grep …」——`方案.py --验`）
  - 新坑一入账，凡待立之法俱红，补毕方绿。
  - 虫洞之法就是这样进化的：把所有的坑一个一个从新法里彻底排除。
- **★上线之律（1014 作者令「新弄出一个方法，要确定它绝对绝对有效；每一个 token 都要用到最正确的地方；坚决不做无用功——D6 那一回是最怕的」）**：凡新法（新器、新席、新令、新段、新流程）：
  - **病须机器量出**：先有数、有据（费审、机械账、逐段比对、盲读之卡处……），⛔凭感觉立法。
  - **前定之验**：试之前写死——比哪个基线、拿什么数、胜几分算胜、停止线；方案之题标「新法」者，`工具/方案.py --验` 无「## 前定之验」（基线、胜、退）即红，⛔开。
  - **一处试**：只在一个单位（一章、一件）试，⛔一上来全推。
  - **胜则推，不胜即退**：退回旧法、入坑账写其由；「再试一回」至多一次（坑①：D6 九轮之痛）。
  - **每一新法须答「它的 token 换回什么」**：换不回质、也省不了钱者，⛔立。
  - 1014 首例：坑㉘ 之「写毕即交」试两章（384、385）——照办之席增而整份重写不降，判「不胜」，退其为治之名，根更正；改以计价（一时档缓存）治，先以试席确证、再以真转录推算，⛔动质。

## 二、每一件任务之环（七步·⛔跳）

1. **开**：`python3 工具/工作流账.py --开`，答四问。
   - 查 `设定/方法账.md` 同类之最优。
   - **逐坑过一遍**：`--开` 印出坑账全部之坑；有效之据须写「坑之检」——本法如何排除之。暂停令在即拒开。
   - **零token之检**：有效之据须写「零token之检：……」——哪些归脚本、哪些非模型不可（坑⑳）。
   - **方案逐环确证**：先立 `设定/方案/W.md`（`工具/方案.py --模板`），逐环写谁办、确证（实据）、时、费、败则；`--开` 先验之，未确证者⛔开。
   - **预审（坑65·1120 W911 环6）**：W913 起之 W9xx（W912 环7 起），方案成而未开——派预审 Run（args: {W, 预审: true}·攻者 ≥2·只读，续跑之守⑤ 许件未开而方案在者）攻其核心之断——Run 须书本方案之路（`设定/方案/W.md`）於提示（深验以其脚本含此路判之；通用之脚本以 args 拼路者，须於提示另书其路之全文，否则拒开）；攻条明列「diff 触 接棒守.兜底之令／⑩之六／坑61 之钉者逐行看」（兜底之隔之声明可虚书）→ `python3 工具/费审.py --记 <Run> "W·预审"` → `python3 工具/方案.py --预审 W <Run>` 机出险行、逐险填环与防（纳或「驳：<由>」）、书判与审之指 → `--开`（深验其 Run 之档）→ 施。开後改取、兜底之隔之声明或逐环（审之指异）→ 方案.验 坏、`--裁` 拒，须复审。虫洞之择并书「- 兜底之隔：不改」或「- 兜底之隔：改——缓存之算：每唤冷 $…、暖 $…；日 $…」。
   - 估费照费审之实 ×1.5。
2. **料**：零 token 汇料（`工具/章料.py N`、料包），席只读此档。
3. **造**：多席独立、各尽全力，蒙名；取最强之骨，嫁接他稿之叫绝。
4. **验**：
   - 机器对账先跑（预筛、诸闸）；模型只判机器判不了的致命。
   - 红了只治那一处；⛔循环，一回不绿即上止损闸。
5. **收**：用 `python3 工具/推.py` 存底并推送，放後台跑；要等它，只等通知，或一回 `python3 工具/推.py --等`（⛔轮询）。
6. **审**：
   - `python3 工具/费审.py <Run ID>`：诸席之费，逐回精算美元（按 message.id 去重），并与界面所示之数核。每 Run 一完即 `--记`。
   - `python3 工具/费审.py --主 <起时> [止时]`：主环之费（亦以美元）。
   - `python3 工具/复盘.py W 题 <Run…> --自 <起时>` 起草。自动填流程、制作过程（提交）、耗费、主环之费、资源分配。
   - 总编辑亲填：产出、效（类、目标、服务目标之费、浪费、机器能办而花token）、与上回比、无用功、刀刃、改进方案、坑。
   - `python3 工具/复盘.py --效账`：看本件与上回同类之比。
7. **进化**：
   - 新坑：`方法坑账.py --立`。旧坑复踩：`--复踩`，并写其治。
   - 修到已守：`--守 号 档`。
   - 法有变：新法先过坑之检（逐坑排除），再升本档之版；方法账记一行。
   - 下回同类须**造之占↑、总费↓、质不劣**，三样俱合方算进化。

**闸守此环**：
- 工作流账 `--裁 取／重造` 先验复盘四节：耗费、无用功、改进方案、坑。
- `复盘.py --验`：坑节须点坑账之号，或写「无新坑」。
- `方法坑账.py --验`（入全测）：未守者须有计且计带限（「限：NNN章」或「限：MMDD」，逾即红），已守者须有格（读者可见之闸；器红级之坑许只在全测），复踩 ≥2 者须有格，已汰者须书代之者，三入口档同步，**本档须点到每一坑**，**待立之新法设计档之「坑之检」须点到每一坑**（1027 执行之核）。
- 工作流账 `--开`：暂停令在即拒开；有效之据须写坑之检。

## 三、各类任务之现行流程

### 三之一·造剧情（全书总案、段案）——现行 v1（W17 实证）

1. 零 token 汇料包。须含已定之细：canon 全卡、全员生死、知之时序（坑⑬）。档 ≤30KB 之令（坑③）。

### 三之二·写一章——现行「造式二代」（381 实证·1013；一代 380 为其前）

- **★作者令（1014）·造之质⛔妥协**：「省钱的所有渠道都不能从折损文章质量方面去省；省下的钱是为了怼回造这一环，让剧情到最高 level。」——执笔之 effort 永照 max，⛔为省钱而降；料与另读之档⛔为省钱而删。**省只许在三处**：计价（缓存之档：诸席一时档，`.claude/settings.json` 之 `subagentPromptCacheTtl`）、机械（归脚本，三之五）、重复（同一字被读两遍、印两遍）。

**一代**：
1. 定位。
2. 三魂、定魂。
3. 三执笔全力各写整章。
4. 独立行家蒙名选稿，只列致命与大进。
5. 合稿，只治这两样。
6. 机闸、逻辑审两回、盲读。
7. 案席、封版。

**实测（380）**：
- 质：致命 0、大进 1，盲读读懂且想读下一章。
- 费：**美元 $164.41**（官方价目精算；界面所示 570 万 token ⛔实耗）、约八时、21 席。诸席缓存读（去重）4.87 亿。
- 分配（美元之占）：造 50%、验 11%、**机器之活 39%（失配）**。执笔来回 106—139，大半在翻料（坑②④⑫）。

**二代**（`设定/方法升级_造式二代.md` 定稿）：
- 章料零 token；⛔定位席；魂并入执笔。
- 按重分配执笔 3／5／7；行家只列致命与大进。
- 合稿交结构化之账；机器之活全归 `造式验.py`、`封版.py`。
- 验一回；回数之限：执笔 ≤12、选 ≤10、合 ≤12、审 ≤8。
- 新立瘦之 `造章.js`（⛔再往 `一章.js` 添式）。

**替换之约**：以 381 对 380 比四样——费、致命、拍库之分、盲读。四样俱不劣，且费降，方以二代替一代。

**读之法**（1015 作者令「写一章精读一章，详记串成从头到尾之链，日後大改不必再读；读法须不停进化，⛔死读书，越读越好、越读越省」）：记席随章精读（读全章，据行家评、盲读、逻辑审），详记（设定/全书记忆/第N章.md）添「亮点」「读之得」二节；诸账由 `工具/记料.py` 一档汇齐（⛔逐档翻）；`工具/剧情链.py` 把诸章详记串成 `设定/全书记忆/剧情链.md`，封版与还账施後即重生、全测验其与详记同。**进化之环**：每回大审之录册逐笔判「该章读之得已提否」，算**读之漏率**——须一回比一回低；每类漏归一问添入读之得之清单（用法.md §六）；记席之费逐章费审记之，⛔读得更细而费升。

**裁之落之律**（1014·坑㉙）：凡新章所赖之裁（剧情庭之 G 号、大升级之改），须在**头一章动笔之前**落进正文——裁而未落、新章先照新裁写，则新章与前文当面相抵，此後每章之验席都为它空耗。守：`工具/欠账闸.py`（零 token 判 G 号落没落）；落法：`工具/还账.py`（席只译结构化之单，器逐字验後方施，行号不移）。W26 还 D6 之欠；造章之料跑 `欠账闸 --章 N` 待 W26 收後立。

### 三之四·总编辑亲手之活（设计、治器、记账）

- **主环亦是费**：主环每一回工具都把整个上下文重发一遍（每回约 13—19 万；1009「二代定稿」一件主环 41 回、约 527 万缓存读，其中轮询等推约六回——坑⑮）。
  - 批量做、少来回。
  - 读档只读所须之段。
  - ⛔轮询；等後台之活，只等通知，或用 `推.py --等`。
- **量器须拿真料核一回**：自测只用造的假料，量不出真转录之形（坑⑯）。
- **多步之命令**：後步依前步者，一律 `&&` 相连（⛔恃 `set -e`——本壳不生效，1013 实测；管道须 `set -o pipefail`，生效）；⛔以换行相隔，前败而後照跑（坑⑰）。
- **立新档前先查同名**：`git ls-files` 查之；提交前 `git status` 见「M」而非「??」即停（坑⑱）。
- **改闸**：只因闸错而改（例：暂停令上盘，坑⑭），⛔为让自己过而松。改必带负测。
- **作者之令**：须有盘上之据，诸器同认（坑⑭）。
- **暂停中**：只许零 token 之活（`python3 工具/暂停令.py --查`）。

### 三之五·机械之活（一切非写作之任务）——现行 v1.8（1013 立·详 `设定/方法升级_机械之活.md`）

- **价在「回数 × 上下文」**：命令零 token，主环每发一回重读整份上下文（机械账 1013：主会话 $389，非写作之活 71%；10-09 起 88%）。故只两样：**回数砍到一、上下文砍到小**。
- **一件一条命令**：一章之收口 `封版.py N --後`＋`推.py`（後台；存底、备份在内）；复盘 `复盘.py`；接手、开工只跑 `自走.py`。
- **候即止**：派出之後结束本回合，等通知；⛔看进度、⛔ps／sleep、⛔为候找活（自走已删找活四条）。
- **长停开新会话**：逾一时之停，新会话读交接档接手；⛔醒大会话（坑㉓）。
- **定时器**：三个 Routine 保持停用；章与章以事件相接。无人值守须作者令，且只许一个新会话之 Routine、令极简、≥ 两时。
- **量**：`python3 工具/机械账.py [起 [止]]` 按类印主环之回与 $；复盘自动印非写作之占与前三类，须逐回降（坑㉔）。
