由：
- 1120 作者令（原话）：「方法上的更新和不断的进化……整体的那个全图也要随之更新」；同日续令（二）：「这个东西它是要随时不断更新和进化的……本来就是为了让我们的工作变得更加的轻松和更加的灵活和自由，和更加的这个高效……我们的执行主义肯定要把所有的这些东西都去执行起来，而不是说你弄出来之後就放那儿囤灰不用了……这不是每次都要用吗？……跟执行主义不是都要结合起来会使用吗？」

## 虫洞之择

- 候甲：留今（图唯随封版·方案手 grep 消费者）——效：图迟一章、机制之流⛔见、方案之消费者恃记性（坑㊱）；费：0；险：图与实相违而治依之（误导）；质：不变。
- 候乙：①图添「机制之流」（mermaid·GitHub 即绘为图）与「近之进化」，俱自码与账机取（巡.yml 等之 on 与 job 之 if、接棒守.兜底之令／钟之令／总编辑／巡警枝、工作流账之裁）；②方法一变图即随：总编辑之治改器／流／法用册而图旧 → 推.py rc 3 ⛔交（只拦总编辑之坐·写书之坐之治照旧），账并认生成之图（两侧俱生成之物：取 ours、⚠ 待下回重生）免冲突；③每件必用：W912 起之方案须有「## 图之用」——逐环所改之件逐件书其「谁跑／谁读」（`方案.py --图 W` 自图机出其节），方案.py 验其覆盖、工作流账 --开 即拦——效：图随方法当回而变，机制入图，每设计必经图（消费者以图为源·坑㊱ 之根治）；费：施约 $45、日常 0（重画约十秒）；险：账并之新支误并 → 回放三章之真并钉之；质：⛔增写书之坐之一字（写书之治⛔拦）。
- 候丙：GitHub autopush 每并後重画而推——效：图随一切之并；费：0；险：动 autopush（关键之路）且 GitHub 为第二写者、与章-N 之图必冲突；质：⛔动关键之路——弃。
- 候丁：推.py 凡推（含写书之坐）自重画而自提交——效：图恒鲜；费：写书之坐每推增约十秒与一提交；险：写书之路增步（拖累写书）、自提交之签名与钩之变；质：违「⛔拖累写书」——弃。
- 取：候乙——由：图当回随方法而变（总编辑之治即方法之变之所出）、机制之流入图、每件之设计必用图（执行主义：图⛔囤灰），而写书之路⛔增一步；冲突以账并之生成之图一支免之（坑63 之由即去）；候丙动关键之路、候丁拖累写书、候甲迟而图⛔用。
